Верзија 2.6 (тестирање): облеката според **просечната** дневна температура (благо 16–22° → пола маици, пола долги ракави, 1 џемпер; свежо 9–16° → помалку горни делови, повеќе слоеви; студено → долги ракави, џемпери, топла јакна), а без прогноза (бесплатно) — климатска проценка според географската ширина и месецот; кога ќе стигне прогнозата, маиците/џемперите/јакните сами се усогласуваат (освен спакуваното и рачно сменетото); бесплатно секој предмет е ×1 и бројките се менуваат рачно со + и −; со Premium бројките се пресметуваат според деновите и времето (по купувањето сите претстојни патувања се ажурираат, освен рачно сменетото); ×1 кај секој предмет освен документите; поголеми копчиња +/− за багажите; кодот на земјата (+389) веќе е внесен кај секое поле за телефон (по најавата, при регистрација и во Акаунт); во Профил ред „Premium“ — купи или управувај со претплатата; Premium се отклучува веднаш по купувањето и прозорецот сам се затвора.

Безбедност (ноември 2026): Firebase 12.19.3+ — поправка за Firestore поради компромитираните eMudhra сертификати (е-пошта од Firebase). Бара Xcode 26.2+, затоа градењето оди на macos-26.

Повеќе градови (Premium): Солун → Лефкада → Миконос во едно патување, со посебен календар и перална за секој град; прогнозата се зема за секој град во неговите денови (на денот на преселба — новиот град), облеката се брои според најдолгиот период без перење, адаптер за секоја држава. Име на патувањето по избор; без него автоматски „Патување во Париз“ / „Greece trip“ (повеќе градови во една држава — државата; повеќе држави — „Грција и Италија“).

Premium по најава: еднаш, веднаш по најавата (по името и телефонот), се појавува целоекранска понуда — пример-карта, „Пробај Premium 7 дена бесплатно“ со чекорите Денес → Ден 7, годишно / месечно („Заштеди 58%“), X и „Продолжи со бесплатната верзија“. Не се покажува ако Premium е активен или App Store не ги вратил цените (без интернет, DSA). Ако пробата е веќе искористена — „Целото патување, спакувано“ со придобивките и „Претплати се“. Одјавата го брише знакот, па по најава со друг акаунт се покажува уште еднаш (`Sources/Views/PremiumOfferView.swift`).

Гардероба — групи и видови: секое парче има група и **вид** — Горни (маица, топ / кроп топ, долги ракави, кошула, џемпер, дуксер, кардиган), Панталони и шорцеви (фармерки, панталони, елегантни, хеланки, шорцеви), Фустани и сукњи (фустан, сукња, комбинезон, вечерен), Јакни и палта (лесна, сако, топла, палто, кабаница), Обувки (патики, сандали, елегантни, штикли, чизми, планинарски, за тренинг), **Плажа и спорт** (костим за капење, спортска облека), Торби, Додатоци. Видот се погодува од името („Сив дуксер“ → Горни · Дуксер). Во листата секое парче се брои само во својот ред (џемперот во „Џемпер / дуксер“, не во маици); ако аутфитите имаат нешто што листата го нема (пр. сукња, костим), редот сам се додава и ја следи бројката од аутфитите додека не се смени рачно. Во гардеробата парчињата се подгрупирани по вид; постоечката облека добива вид според името, а тоа што не може да се погоди се подредува со еден допир („N парчиња без вид“). На сликата од аутфитот маицата е под џемперот, а џемперот под јакната (`Sources/Wardrobe/WardrobeKind.swift`).

Известувања од пријателите (push): „Ана те додаде во патувањето“, „Мила се приклучи“, „Ана те означи да носиш: Чадор“, „Ана ќе носи: Фен“ / „…наместо тебе“ (повеќе одеднаш → една збирна порака). Ги праќа функцијата `functions/index.js` (Firebase Cloud Functions, europe-west1) кога ќе се смени `trips/{id}`; кој ја направил промената се знае од најавата или од полето `editedBy`. Апликацијата го чува токенот во `users/{uid}.fcmTokens` (+ `lang`, `friendAlerts`), го брише при одјава; допир → се отвора патувањето. Во Профил: „Известувања од пријателите“. Логиката се проверува со `npm test` во `functions/`.

Еднаш за известувањата:
1. Firebase → Blaze план.
2. Apple Developer → Keys → нов клуч „Apple Push Notifications service (APNs)“, Environment: Sandbox & Production → .p8 во Firebase → Project settings → Cloud Messaging → APNs Authentication Key (Key ID + Team ID).
3. Apple Developer → Identifiers → com.valise.packing → Push Notifications ✓ → Save.
4. Google Cloud Console (проект valise-76aa0) → IAM & Admin → Service Accounts → Create → име `github-deploy`, улога **Owner** → Keys → Add key → JSON → содржината во GitHub → Settings → Secrets → Actions → `FIREBASE_SERVICE_ACCOUNT`.
5. GitHub → Actions → „Firebase — известувања и правила“ → Run (ги качува и функцијата и `firestore.rules`).

Волшебник: екранот го следи полето што го пополнуваш (над тастатурата), новиот град веднаш ја отвора тастатурата, по изборот на датуми лизга до следниот град; кај повеќе градови „Пристигнување → Заминување“, а следниот град не може да почне пред заминувањето од претходниот (ако првиот се продолжи, следните се поместуваат).

Потсетници (локални известувања, без сервер): 3 дена пред тргнување во 19:00 („уште N работи на листата“, само ако има неспакувано), ден пред во 19:00 (што фали / „сè е спакувано“), на денот во 08:00 „Пред излез од дома“ (Premium) и ден пред враќање во 20:00 (патувања од 3+ дена). Се закажуваат одново по секоја промена, за бројките да се точни; допир → се отвора патувањето. Дозволата не се бара при старт — во патувањето се појавува „Да те потсетам?“; во Профил има прекинувач „Потсетници за патувања“ (`Sources/Notifications`). Push известувања (пр. „Ана те додаде во патување“) бараат сервер (Cloud Functions, Blaze) и APNs клуч — следен чекор.

Гардероба — филтер и автоматски стикер: под „Парчиња“ има избор на група (Сите · Горни делови · Фустани и сукњи…, стандардно „Сите“, само групите што имаат парчиња). Стикерот се сече сам веднаш по сликањето — од повеќе предмети на сликата се зема главниот (најголем и најблиску до средината; кај обувки двете); ако не успее или има лице → рачно означување, а по автоматското сечење има „Не е добро исечено? Означи рачно“. „Исечена слика“ и понатаму се означува рачно.

Избришан акаунт: при секое отворање и враќање во апликацијата се проверува кај Firebase дали акаунтот уште постои; ако е избришан или блокиран (пр. од Firebase Console), телефонот веднаш се одјавува и сè лично се брише.

Еден број — еден акаунт: пред да се зачува телефонот (при регистрација, во чекорот по најавата и во Акаунт) апликацијата проверува во Firebase дали шифрираниот број веќе е на друг акаунт → „Овој број веќе е додаден во друг акаунт…“ и бројот не се зачувува. Сменет или избришан број се ослободува за друг. Поканите по број ги добива само акаунтот што го има бројот. Новите правила во `firestore.rules` треба да се објават (Firebase Console → Firestore → Rules → Publish). Без SMS потврда: првиот што ќе го внесе бројот го задржува.

Крај на претплатата: Premium се проверува при секое враќање во апликацијата и точно во моментот на истек (ако е отворена), па откажана/истечена претплата веднаш се заклучува — ништо не се брише, сè се враќа со нова претплата. Ако плаќањето не помине, а во App Store Connect е вклучен **Billing Grace Period**, Premium останува додека Apple се обидува повторно, со порака „Плаќањето не помина“ во Профил. Откажана претплата пишува „Откажано · трае до …“.

Име: **Tripdrobe** — во App Store Connect → App Information → Name: `Tripdrobe: Trip Outfit Planner`. Внатрешните имиња (проект, Bundle ID `com.valise.packing`, ID на производите) остануваат исти — корисниците не ги гледаат.

## Претплата во App Store Connect (еднаш)
Бесплатно: неограничени патувања само со листа за пакување. Premium: прогноза, авиокомпании и багаж, гардероба и аутфити, пријатели, Story, „Пред излез“, теми.

1. **Agreements, Tax, and Banking → Paid Apps** — активен (банка + даночен формулар). Без ова производите не се вчитуваат ни во TestFlight.
2. Апликацијата → **Monetization → Subscriptions** → **+ Subscription Group**: `Tripdrobe Premium`.
3. Во групата **+** два пати:
   - `com.valise.premium.yearly` — Duration **1 Year**, цена **$19.99**, **Introductory Offer → Free Trial → 1 Week**.
   - `com.valise.premium.monthly` — Duration **1 Month**, цена **$3.99**.
   - За секоја: Localization (англиски, по желба и македонски): Display Name и Description; **Review Screenshot** (слика од екранот Premium).
4. Во описот на апликацијата (App Store) додај линкови до Условите за користење и Политиката за приватност — Apple го бара тоа за претплати.

Во TestFlight купувањата се бесплатни, а претплатите се обновуваат забрзано (секој ден), за да може да се проба обновувањето.

## TestFlight (официјално тестирање) — без Mac
Workflow-от `.github/workflows/testflight.yml` прави архива, ја потпишува преку App Store Connect API клучот и ја качува на TestFlight. Тест-верзијата за Sideloadly (`build-ipa.yml`) останува иста.

**Еднаш:**
1. developer.apple.com → **Certificates, IDs & Profiles → Identifiers → +** → App IDs → App → Bundle ID `com.valise.packing` (Explicit). Вклучи **Sign in with Apple**, а во *App Services* — **WeatherKit**.
2. appstoreconnect.apple.com → **Apps → + → New App**: iOS, име (привремено), Primary Language, Bundle ID `com.valise.packing`, SKU `valise001`.
3. App Store Connect → **Users and Access → Integrations → App Store Connect API → Team Keys → +** → име `GitHub`, улога **Admin** → Generate. Симни го `.p8` (може само еднаш), запиши **Key ID** и **Issuer ID**.
4. developer.apple.com → **Account → Membership details** → **Team ID**.
5. GitHub репото → **Settings → Secrets and variables → Actions → New repository secret**: `APPLE_TEAM_ID`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8` (целата содржина на .p8, отворен со Notepad).
6. Firebase → Authentication → Sign-in method → **Apple** → Enable.

**Секое качување:** GitHub → **Actions → „Качи на TestFlight“ → Run workflow**. За 10–30 минути изградбата е во App Store Connect → TestFlight. Бројот на изградбата се зголемува сам.

Во TestFlight изградбата се вклучени Најава со Apple и Apple Weather (`VALISE_STORE_BUILD = YES`). Во Sideloadly изградбата — исклучени (Open-Meteo).

GitHub автоматски гради `Valise.ipa` при секое качување на код (таб **Actions**).

## Добивање на .ipa
1. Таб **Actions** → последната изградба „Изгради IPA“ (зелена ✓).
2. Долу кај **Artifacts** → **Valise-ipa** → се симнува zip.
3. Отпакувај → `Valise.ipa` → повлечи во Sideloadly.

Рачно повторно градење: Actions → „Изгради IPA“ → **Run workflow**.

Ако изградбата падне (црвено ✗), отвори ја — грешките се прикажани на врвот, во делот *Грешки при изградба*.

## Структура
- `Sources/` — Swift код (екрани во `Sources/Views/`, гардероба во `Sources/Wardrobe/` и `Sources/Views/Wardrobe/`)
- `Assets.xcassets/` — иконата и акцентната боја
- `project.yml` — поставки за проектот (XcodeGen)
- `.github/workflows/build-ipa.yml` — автоматската изградба
